# ScoutCapture refactor plan

## Starting point

- Branch: `codex/refactor-test`, based on source commit `4e04061` (app version 1.2, build 19).
- The original `main` working tree has separate local edits and is not used for these changes.
- The prechange simulator test run produced 1,108 passes and 105 failures before one test stalled and the run was stopped. A later full run on the refactor branch reached 238 completed tests (208 passes, 30 failures across five classes) before it was stopped because offline-replay fixtures repeatedly contacted `example.supabase.co` and made the broad gate too slow and unreliable. Those failures are not yet attributed to refactor changes. One property-status failure reproduced in isolation (`testCachedExportedFreshRemoteOccupiedByOtherBlocksEntry`, cache status was `nil` instead of `occupied`). Tracing showed a startup authentication callback arriving after its fixture installed a fake user; that callback cleared the organization scope and status cache. Cancelling the startup callback when observation stops and stopping the unused observer in this fixture made the isolated test pass. The other prechange failures remain unclassified, so the full suite is not yet a reliable pass/fail gate.

## Test baseline investigation

After cancelling the stale authentication startup callback in the property-status test fixture, the full `Phase2C27FZ4PropertyStatusDiagnosticsTests` class ran to completion: **75 tests, 58 passing cases, 17 failing cases (35 failed assertions)**. The isolated case that first exposed the callback race passes, along with two neighboring entry tests. The initial failing cases clustered as follows:

| Area | Failing cases | Examples |
| --- | ---: | --- |
| Cross-device ownership, lock, and badge state | 7 | Same user on another device treated as owner by an older test, but current code treats the device as the owner when one is recorded; pending-export badge and lock expectations also differ. |
| No-ZIP release and local reconciliation | 3 | Stale draft or released status remains visible; one persistent-data reconciliation assertion checked before a scheduled refresh completed. |
| User-facing lock wording | 6 | Tests expect older phrases such as “on device”; the app now renders a short bullet-separated description. |
| Missing-row preflight reason | 1 | The app reports `fresh_read_missing_row`; the test expects `missing_property_status_row`. |

Source history confirmed that the six lock-message tests expected older copy. After updating only those assertions, the full class reran with **64 passing and 11 failing cases (27 failed assertions)**. The missing-row test expected an older diagnostic reason and now passes in isolation. Four pending-export tests expected both a Pending Export badge and a Lock badge; Build 19 intentionally shows the Pending Export badge while still blocking entry, and all four pass with that expectation. The persistent-data reconciliation test checked before the app's 180 ms debounce; after waiting for the actual refresh, it passes. For no-ZIP release, the app correctly hides the stale current-device badge while retaining the remote cache record, and it preserves a lock owned by another device. The tests now verify those visible outcomes. A known empty local draft incorrectly showed a Draft badge; the compare answer now treats that current-device draft as a no-op, and adjacent owner and non-owner badge tests pass. The two remaining tests expected a same-user, different-device draft to be treated as owned locally. The current Build 19 policy treats the recorded device as owner, and the tests now assert its existing lock and cache behavior without changing runtime policy. The full class now runs **75 tests with 0 failures**. This class is one slice of the earlier 105-failure Build 19 run; the other failures are still unclassified.

One coordination failure, `testUntouchedLocalSessionOccupancyClaimWritesRemoteMarker`, also reproduced alone. Its fixture faked the occupancy write but not the newer `claim_property_status` RPC, so the app tried `example.supabase.co`, failed the status claim, released the occupancy marker, and blocked entry. The same fail-closed branch exists in Build 19. A Debug-only RPC response override now lets the fixture provide a deterministic success response; production continues to block entry if the real status claim fails. Two other tests held stale expectations: one expected the remote-occupancy message when the current local session is active, and a hand-written legacy queue payload omitted the required `is_archived` property field. With those test-only corrections, all **23 coordination tests pass**. The class still logs unrelated profile lookup attempts to the placeholder host, so it is not fully network-independent.

The full `Phase2C07bMediaBackfillTests` class now passes **54 tests with 0 failures**. Its older fixture created organizations without selecting one, while current media recovery limits inspection and retry to an active, accessible organization. The fixture now sets that context and stops its startup auth observer. Tests that switch organizations use the matching Supabase context; two audit tests pass fixed records to the audit helper so local refreshes cannot change their input mid-assertion. Diagnostic checks now verify the current retry-cap and redaction rules, including the case where a background metadata update removes optional error details. These are test-only changes; media backfill and recovery code did not change. Other broad-suite failures remain unclassified.

The full `Phase2C10OfflineReplayTests` class now passes **33 tests with 0 failures**. Its session-queue fixture now provides an idle status row and explicitly saves the new session shell before expecting a queued write, matching Build 19. Date assertions use whole-second timestamps because queue storage rounds timestamps; a global last-error assertion was removed because unrelated background network requests can replace it. The class also exposed one runtime bug: a permissions failure naming the `sessions` table was being marked as permanent parent-`properties` debt, stopping retries. Auto-acknowledgement and stale-parent classification now require an error naming `properties`, leaving sessions-table failures queued for retry and manual review. The diagnostic classifier now recognizes the hyphenated `row-level security` phrase.

`ClientPortalPriorityTradeSyncTests` still has **7 failing cases out of 53 tests (11 failed assertions)** when run alone on the refactor branch. The pre-refactor Build 19 test log shows the same seven cases failing, including resolution rejection, reopening, and supporting-metadata expectations. They are existing baseline failures, not evidence of a refactor regression. Keep portal synchronization out of the green smoke gate until the intended behavior and fixture inputs are reconciled; no portal runtime code was changed during this audit.

The seven portal cases now have a code-path map: a status-only overlay advances the local timestamp and counts as applied; pending-review lineage intentionally omits `observation_updates` because the database constraint accepts only active/resolved rows; resolved and pending-review shots retain the flagged issue marker in the current metadata sync; a generic `status_changed` activity does not carry the explicit reopen flag required for a resolved issue; and rejection retains the photo reference while the test labels newer metadata as stale. These are current Build 19 behaviors. The intended user-facing semantics still need resolution before changing assertions or runtime logic; the smoke gate leaves this class out and continues to report its seven failures separately.

## Completed on the refactor branch

1. **Preset ownership.** One shared `DetailTypesModel` now serves standard and fast capture. The second model and its duplicate persistence logic were removed. Focused tests cover cross-view edits, persistence, and fast capture's Overview selection.
2. **Credential exposure check.** A value-redacting scanner checks tracked files and optionally a built app for recognizable privileged keys. A pull request workflow runs the source scan. The current source and Build 19 / refactor Debug and Release app bundles contain no recognized privileged credentials. The Supabase publishable key remains in the app as a public client identifier.
3. **ZIP export code.** Three in-memory ZIP writers and duplicate entry readers were consolidated into `StoredZipArchive`. Focused tests and an independent ZIP reader verified archive paths, file contents, and checksums. ZIP32 bounds now fail explicitly.
4. **Export memory use and migration ZIP.** Export enumeration keeps file URLs rather than all photo bytes. The active export paths stream ZIP contents in 64 KiB chunks, copy staged photos at the file level, and read only the ZIP directory during validation. The temporary migration export now uses the same streaming ZIP writer while preserving its directory entries and per-entry progress updates. A standalone optimized writer check with 64 files totaling 128 MiB found temporary read buffers accumulating to about 278 MB peak memory; releasing them per chunk reduced measured peak memory to about 8 MB. An independent ZIP reader verified all 65 entries and checksums, and focused app ZIP tests pass. This measures the writer process, not the full app export flow.
5. **Migration import path safety.** The importer now validates every Application Support and Documents file path before replacing local data. Traversal, absolute-like, repeated-separator, backslash, and control-character paths fail import. Focused tests verify valid nested paths and that a malicious archive leaves existing preferences intact.
6. **Backend configuration extraction.** `SupabaseRuntimeConfiguration`, cutover phase and rollback descriptions, and `BackendFeatureFlags` moved unchanged from `AppState.swift` into `BackendConfiguration.swift` (561 lines). A byte-for-byte comparison confirmed the definitions were unchanged. The shared XCTest environment helper became internal to the app module so the moved Release code can reference it; its logic did not change. Two existing manual snapshot buttons made one old source-count assertion stale; after aligning it to the unchanged UI, all 40 focused configuration and cutover tests pass. The iOS Release build succeeds.
7. **Coordination regression gate.** The session-coordination fixture now supplies the status RPC response in Debug tests, so its 23 cases can check the existing Build 19 coordination behavior without a live placeholder server. The Release path keeps the real RPC and its fail-closed handling.
8. **Media regression gate.** The media fixture now establishes an active organization and uses fixed inputs for audit-only cases. All 54 media backfill tests pass without changing runtime media behavior.
9. **Offline-replay regression gate and RLS safeguard.** All 33 replay tests pass. A sessions-table permission error now remains retryable; only a confirmed parent-properties error follows the existing terminal-debt path.
10. **Migration import integrity preflight.** Before clearing local data, import now checks the central-directory shape, streams every restore payload through the shared ZIP CRC32 calculation, and parses the preferences payload. Corrupt file bytes, malformed preferences, and a mismatched directory entry count leave existing preferences untouched in focused tests. A valid migration archive restores files and preferences into isolated test roots. This reduces the chance of erasing local data for a damaged archive; it does not make the later replacement sequence atomic.
11. **Streaming migration restore.** Restored files now copy through 64 KiB chunks to a temporary file and are moved into place only after their checksum passes. The same payload reader serves preflight, file extraction, and the small preferences JSON. A valid multi-chunk archive restores exact bytes in the isolated import test; all archive and import focused tests pass. The importer still owns a separate ZIP directory parser.
12. **Shared ZIP directory reader.** The migration importer and export entry listing now use one central-directory parser in `StoredZipArchive`. The importer retains its user-facing error messages for unsupported and malformed archives. All archive and import focused tests pass, including valid restore and corrupt archive rejection.
13. **Shared session export packaging.** Standard and pending exports now call one routine for ZIP staging, file existence checks, and expected-path verification while retaining their existing error domains and debug root checks. A 24-photo, multi-file simulator test exercises export enumeration, packaging, archive paths, and copied bytes. A host-side integration check using the actual `StorageRoot` and `SessionExportZip` code then packaged 100 synthetic photos totaling 200 MiB on the Samsung drive and verified every archived path and photo byte. The full app UI export with real photos remains to be checked.
14. **Export filename cleanup.** Standard and fast export now use one ZIP filename rule with their existing property, session, and fallback inputs. Two private photo filename helpers with no call sites were removed. Pending export keeps its separate whitespace normalization rule.
15. **First `AppState` split.** Snapshot upload and cloud status display models moved unchanged into `AppStateSnapshotStatusModels.swift`, reducing the main file by 173 lines. A byte-for-byte comparison and focused disabled-upload status tests confirm the definitions and visible status text are unchanged. Session lifecycle and synchronization policies remain in `AppState`.
16. **Diagnostics model extraction.** Snapshot restore, media recovery, offline queue, and local diagnostics types moved unchanged into `AppStateDiagnosticsModels.swift`. A byte-for-byte comparison and four focused tests across those areas pass. This removes another large data-model block from `AppState`; behavior and storage paths remain in the original type.
17. **Offline replay policy extraction.** Backoff timing, launch replay limits, and queued mutation eligibility moved unchanged from `AppState` into `OfflineReplayPolicy.swift`. The full 33-test offline replay class and two snapshot retry tests pass. Snapshot retry eligibility now uses the same due-date decision as queued mutations, while retaining its own terminal status. This keeps the retry rules in one small, reviewable unit without changing either queue or its stored format.
18. **Repeatable refactor smoke gate.** `tools/run_refactor_smoke.sh` runs seven previously verified classes using external derived data by default. A combined serial run passed **211 tests with 0 failures**, covering property status, session coordination, media recovery, cutover, offline replay, ZIP archives, and migration import. The seven known pre-refactor portal sync failures remain outside this gate and are documented above.
19. **Export failure cleanup.** The shared ZIP packager now removes its temporary archive if packaging fails before the final move. Successful export bytes and paths are unchanged.
20. **Larger export integration check.** A temporary host harness compiled the repository's actual export enumeration and packaging sources, created 100 synthetic 2 MiB photos on Samsung, and verified all 100 archived paths and payloads in a 209,729,784-byte ZIP. The process stayed below 10 MiB of resident memory while writing. This validates packaging at a realistic size, but does not exercise the app UI or a real camera library.

## Next steps, in order

1. **Restore a trustworthy test baseline.** The property-status (75), coordination (23), media-backfill (54), configuration/cutover (40), and offline-replay (33) classes now pass as focused gates. Group and reproduce the remaining prechange failures, including the seven portal sync cases, identify shared simulator or test-data contamination, and establish a full-suite gate. Do not attribute existing failures to the refactor.
2. **Validate archive integration at realistic size.** The shared writer passed a 128 MiB standalone archive check, and the actual package path passed a 200 MiB synthetic photo check. Next exercise the full app export UI with a large real photo set and compare its layout with Build 19. Keep ZIP32 limits visible to users or add ZIP64 support if real sessions can exceed them. Migration restore now streams files and uses the shared ZIP directory reader. Path and payload integrity preflight run before local data is cleared; a fully atomic replacement still needs a separate design.
3. **Split `AppState` by responsibility.** Snapshot status and diagnostics models now have their own files. Extract session lifecycle and synchronization policies behind narrow interfaces, one behavior at a time, with characterization tests for state transitions and offline retry. Avoid a whole-file rewrite of the remaining large type.
4. **Consolidate configuration.** The typed backend settings now have their own file. Continue consolidating scattered environment overrides and diagnostic redaction into that layer, with characterization tests for precedence and production rollout gates.
5. **Remove remaining duplication.** Standard and pending ZIP packaging share a helper, and standard/fast ZIP naming is shared. Continue consolidating repeated report packaging helpers and remaining file naming rules once the test baseline can detect behavior changes.
6. **Protect security boundaries.** Review deployed Supabase RLS and storage policies against the checked-in migrations; verify service-role credentials remain only in server environments. The checked-in migration creates `scoutcapture-originals` as a private bucket, while app code uploads and downloads directly with the client. No `storage.objects` policy for that bucket appears in the checked-in migrations, so inspect the live policy state before changing storage behavior. The repository and app bundle scan cannot prove the live database policies are deployed or correct.
7. **Add continuous verification.** Run the chosen smoke suite, archive tests, and credential scan on pull requests. Add a built-app credential scan in a build environment with enough storage.

Each extraction should be a separate commit with a build, focused behavior tests, and a review of user-visible export or capture behavior before merging to `main`.
